## Как работать с Ланой

- Общайся по-русски, короткими понятными шагами. Лана осваивает Python и VS Code; объясняй, что делает команда и какой результат ожидать.
- Для изменений в коде сначала назови план и ожидаемые файлы, затем выполняй только текущий согласованный рабочий продукт (РП).
- Не переходи к следующему РП без просьбы Ланы.
- Перед командами, которые устанавливают зависимости, удаляют или перезаписывают файлы, меняют системные настройки либо обращаются к сети, объясняй действие и дождись подтверждения Ланы.
- Не удаляй и не перезаписывай существующие файлы, пока не проверил их содержимое и не объяснил необходимость.
- Если контекст, инструкция или данные противоречат друг другу, не угадывай — задай Лане короткий вопрос.
- После каждого этапа покажи, что изменилось, как проверить результат и какой следующий шаг.

## Принятые решения MVP

- Бот получает отдельными сообщениями скриншоты планировщика «план» и «факт», распознаёт задачи, сохраняет их и сравнивает план с фактом.
- Дата событий по умолчанию берётся из даты отправки сообщения в часовом поясе Europe/Moscow. Бот просит подтвердить дату или ввести другую.
- Если время не напечатано на плашке, начало и конец определяются по высоте плашки относительно шкалы времени слева.
- Плановые и фактические строки хранятся отдельно. Связь внутри дня строится по названию задачи; время и длительность не участвуют в сопоставлении. Для MVP предполагается, что одинаковых названий задач в один день нет.
- Фактическая строка с плановым цветом проекта означает частичное выполнение; цвет факта из справочника означает выполнение. Плановая строка без пары в факте считается невыполненной; строка факта без пары в плане — внеплановой.
- Неопределённые названия, времена, даты и проекты не додумываются: они требуют уточнения.

## Текущий РП: Z-005

**Результат:** локальный Python-проект календарного бота с виртуальным окружением и минимальной структурой файлов.

**Среда Ланы:** Windows, VS Code, Python 3.14.2. Пользовательская папка `C:\Users\snkas\calendar_bot` уже создана. Пока не считай её клоном GitHub: проверь наличие `.git` и удалённый репозиторий прежде, чем работать с ней как с кодовой базой.

### Порядок выполнения

1. Проверь открытую в VS Code папку, наличие Git и вывод `git remote -v`. Убедись, что открыт именно клон `snkasatkina-wq/zerocoder`.
2. Если папка не является клоном, сначала проверь, что в ней нет нужных файлов. Не удаляй и не перемещай файлы. Если папка не пустая, остановись и предложи безопасно клонировать репозиторий в отдельную папку. Если она пустая, объясни Лане, как клонировать существующий репозиторий туда.
3. Создай виртуальное окружение Python 3.14 в корне клона:
   ```powershell
   py -3.14 -m venv .venv
   ```
   Активация необязательна: для проверок можно вызывать `.venv\Scripts\python.exe` напрямую, чтобы не менять Execution Policy PowerShell.
4. Создай минимальный каркас в корне репозитория: `main.py`, `README.md` и базовый `.gitignore` для `.venv/`, `__pycache__/` и файлов `*.py[cod]`. Не добавляй Telegram-библиотеку, токен, API-ключ, подключение к PostgreSQL или обработчики сообщений — это другие РП.
5. В `main.py` добавь только минимальную проверяемую точку входа без внешних библиотек. Например, вывод сообщения о запуске каркаса.
6. Проверь запуск:
   ```powershell
   .\.venv\Scripts\python.exe main.py
   ```
   Покажи Лане ожидаемый и фактический вывод. Затем проверь `git status --short`: файлы виртуального окружения не должны попадать в список изменений.
7. Покажи diff и перечень созданных файлов. Не отправляй изменения в GitHub и не делай commit без отдельной просьбы Ланы.

### Критерии завершения Z-005

- VS Code открыт на клоне правильного GitHub-репозитория.
- В корне клона есть `.venv/`, `main.py`, `README.md`, `.gitignore`.
- `main.py` успешно запускается через интерпретатор из `.venv`.
- Зависимости Telegram и секреты не добавлены.
- Лана видит diff и понимает, что создано.
